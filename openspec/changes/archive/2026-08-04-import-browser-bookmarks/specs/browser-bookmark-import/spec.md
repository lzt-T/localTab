## Purpose

让用户在明确授权后直接读取当前浏览器的书签层级，预览转换结果，并将有效书签安全追加到 LocalTab 的本地网址工作区。

## ADDED Requirements

### Requirement: 按需申请浏览器书签权限
系统 MUST 将浏览器书签访问声明为可选权限，并 SHALL 只在用户主动发起浏览器书签导入时请求该权限。未授权或拒绝授权 MUST NOT 影响 LocalTab 的新标签页、搜索、快捷收藏、数据备份或其他现有功能。

#### Scenario: 安装或升级扩展
- **WHEN** 用户安装或升级包含该能力的 LocalTab
- **THEN** 系统不在安装或升级阶段要求用户授予浏览器书签权限

#### Scenario: 用户发起导入
- **WHEN** 用户点击从浏览器导入书签并尚未授权
- **THEN** 系统先说明只读用途，再通过浏览器原生授权流程请求书签权限

#### Scenario: 用户拒绝授权
- **WHEN** 用户拒绝浏览器书签权限
- **THEN** 系统说明未能读取书签且不创建任何 LocalTab 数据，其他功能保持可用

### Requirement: 只读获取并释放权限
系统 SHALL 在获得授权后读取浏览器提供的完整书签树，MUST NOT 创建、更新、移动或删除任何浏览器原书签，并 SHALL 在完成读取或读取失败后释放本次获得的书签权限。

#### Scenario: 成功读取书签树
- **WHEN** 用户授予权限且浏览器成功返回书签树
- **THEN** 系统仅保留生成导入预览所需的内存数据并释放书签权限

#### Scenario: 读取书签失败
- **WHEN** 浏览器书签 API 在授权后读取失败
- **THEN** 系统释放书签权限、显示失败反馈且不写入 LocalTab 数据

#### Scenario: 浏览器不支持书签 API
- **WHEN** 当前扩展运行环境不提供可用的浏览器书签 API
- **THEN** 系统说明当前浏览器不支持直接导入且其他功能保持可用

### Requirement: 将书签层级转换为 LocalTab 结构
系统 SHALL 将包含有效网址的浏览器顶层书签容器转换为新的 LocalTab 分类，将分类直属网址保留为直属网址，并将后续层级文件夹转换为 LocalTab 文件夹。超过 LocalTab 两级结构的目录 MUST 使用由各级名称组成的路径名称展平，且空目录 MUST 被跳过。

#### Scenario: 转换顶层书签容器
- **WHEN** 浏览器书签栏、其他书签或移动书签等顶层容器包含有效网址
- **THEN** 系统为每个非空容器生成一个新的 LocalTab 分类并保持容器原有顺序

#### Scenario: 转换分类直属网址
- **WHEN** 一个网址直属于浏览器顶层书签容器
- **THEN** 系统将其生成为对应 LocalTab 分类的直属网址并保持原有顺序

#### Scenario: 转换嵌套文件夹
- **WHEN** 一个网址位于顶层容器下的多级文件夹“开发 / 前端 / React”中
- **THEN** 系统在对应分类下生成名为“开发 / 前端 / React”的 LocalTab 文件夹并将网址放入其中

#### Scenario: 跳过空目录
- **WHEN** 浏览器文件夹及其全部后代都不包含有效网址
- **THEN** 系统不为该目录生成分类或文件夹

#### Scenario: 导入分类与现有分类重名
- **WHEN** 待导入分类名称已经存在于 LocalTab
- **THEN** 系统为新分类生成可区分的导入后缀名称且不合并或修改现有分类

### Requirement: 校验网址和处理重复项
系统 MUST 只导入使用 HTTP 或 HTTPS 协议的书签网址，并 SHALL 使用书签标题、域名和完整网址依次生成可识别的标题回退。系统 MUST 在同一待导入分类范围内按完整 URL 跳过后续重复项，但 SHALL 允许相同 URL 分别存在于不同分类。

#### Scenario: 导入有效网址
- **WHEN** 书签包含 HTTP 或 HTTPS URL 和非空标题
- **THEN** 系统在导入计划中保留其 URL、标题和原有相对顺序

#### Scenario: 书签标题为空
- **WHEN** 有效书签没有可用标题
- **THEN** 系统使用网址域名作为标题，并在域名不可用时使用完整 URL

#### Scenario: 遇到不支持的协议
- **WHEN** 书签使用 `javascript:`、`data:`、`file:`、浏览器内部协议或其他非 HTTP(S) 协议
- **THEN** 系统跳过该书签并将其计入无效项目统计

#### Scenario: 同一导入分类包含重复 URL
- **WHEN** 同一待导入分类的多个位置包含完全相同的 URL
- **THEN** 系统只保留首次出现的网址并将后续项目计入重复统计

#### Scenario: 不同分类包含相同 URL
- **WHEN** 不同待导入分类分别包含完全相同的 URL
- **THEN** 系统在两个分类中都保留该网址

### Requirement: 导入前提供结果预览
系统 SHALL 在写入前展示将要创建的分类、文件夹和网址数量，以及因重复、无效或不支持而跳过的项目数量，并 MUST 要求用户明确确认后才写入数据。

#### Scenario: 展示有效导入预览
- **WHEN** 书签树转换出至少一个有效网址
- **THEN** 系统展示导入统计和将创建的分类名称，并提供确认与取消操作

#### Scenario: 没有有效网址
- **WHEN** 书签树为空或所有书签都被跳过
- **THEN** 系统展示没有可导入网址的反馈且不提供确认写入操作

#### Scenario: 用户取消预览
- **WHEN** 用户在预览阶段取消导入
- **THEN** 系统关闭导入流程且不创建、修改或删除任何 LocalTab 数据

### Requirement: 原子追加导入
系统 SHALL 将确认后的分类、文件夹和网址追加到现有 LocalTab 数据，并 MUST 在一个原子操作中完成全部写入。系统 MUST NOT 覆盖现有分类、网址、文件夹、Dock、搜索设置、背景或其他系统设置。

#### Scenario: 成功确认导入
- **WHEN** 用户确认一个有效导入预览且全部数据写入成功
- **THEN** 系统追加全部计划记录、保持现有数据不变、刷新页面数据并展示实际导入统计

#### Scenario: 导入写入失败
- **WHEN** 任一计划记录写入失败
- **THEN** 系统回滚本次导入的全部写入、保留导入前数据并展示失败反馈
