## Context

当前搜索框由 `SearchInput` 统一渲染搜索引擎选择器、文本输入、键盘提示和快速搜索结果。`useSearchEngine` 已提供浏览器默认搜索支持状态、当前引擎和自定义引擎数据，`BrowserSearchService` 已通过 Chromium 搜索 API 执行浏览器默认搜索。本次设计复用这些状态和能力，具体行为以 `specs/local-link-quick-search/spec.md` 为准。

## Goals / Non-Goals

**Goals:**

- 让选择器文案准确表达当前搜索策略，而不是显示配置操作。
- 压缩桌面端选择器的最小宽度，使输入区域保持视觉主位。
- 让占位文案和键盘提示随语言及快速搜索状态保持一致。
- 复用现有搜索引擎菜单、状态和搜索服务，不引入新的状态来源。

**Non-Goals:**

- 不改变本地网址匹配、排序和执行逻辑。
- 不改变浏览器默认搜索能力检测及不支持时的现有回退行为。
- 不重新设计搜索结果面板、添加搜索引擎弹窗或搜索框整体布局。

## Decisions

### 1. 从现有搜索策略状态派生选择器文案

继续根据当前自定义引擎、浏览器默认搜索支持状态和初始化状态派生展示名称。浏览器默认搜索可用且未选中自定义引擎时使用精简后的“浏览器默认”；选中自定义引擎时显示其名称；浏览器能力不可用且没有自定义引擎时保留现有引导状态。

选择这一方案是因为展示状态与实际搜索分发使用相同的数据来源，可以避免额外 UI 状态与搜索行为不一致。未采用固定显示“浏览器默认”的方案，因为部分运行环境可能无法调用浏览器默认搜索 API。

### 2. 保持添加操作位于现有菜单底部

保留搜索引擎菜单中的分隔线和“添加搜索引擎”操作，不把添加操作作为选择器的常规状态。这样当前状态与配置操作职责清晰，同时不改变已有添加流程。

未采用独立设置按钮，因为这会扩大本次调整范围并增加重复入口。

### 3. 在现有响应式规则内压缩选择器

保留窄屏仅显示图标的现有行为，只收紧桌面断点下选择器的最小宽度和横向内边距。文案继续使用截断保护，避免自定义引擎名称过长时挤压输入框。

未采用完全隐藏选择器文案的方案，因为桌面端仍需要让用户识别当前搜索策略。

### 4. 直接使用快速搜索面板状态切换键盘提示

使用现有快速搜索面板可见状态决定提示内容。面板关闭时仅显示 Enter；面板打开且包含可选择项时显示上下方向键和 Enter。该提示是现有状态的纯派生值，不新增 React 状态。

未采用始终显示完整快捷键的方案，因为方向键只在结果导航场景中有意义。

### 5. 仅更新现有国际化资源

调整简体中文和英文的浏览器默认名称及搜索占位文案，组件继续通过现有翻译键读取文本。键盘按键名称保持为语言无关的视觉标记。

## Risks / Trade-offs

- [精简后的选择器文案可能无法透露实际搜索提供商名称] → 保留“浏览器默认”这一策略名称，不推测或缓存浏览器未公开的提供商信息。
- [键盘提示切换可能造成宽度轻微变化] → 保持提示容器靠右并使用固定的紧凑样式，不改变输入区域主布局。
- [浏览器默认搜索 API 不可用时无法满足默认搜索行为] → 保留现有能力检测、提示和自定义引擎回退流程。

## Migration Plan

本次变更不涉及数据迁移。发布时替换现有文案和提示条件即可；如需回滚，恢复原翻译文本及始终显示完整键盘提示的渲染逻辑。
